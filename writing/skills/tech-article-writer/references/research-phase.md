# 自动调研阶段

> 设计参考：`stanford-oval/storm` 的多视角知识收集、调研增强大纲和带引用写作流程。

## 目标

在确认写作策略后、生成大纲前完成调研。先建立可追溯的事实基础，再决定文章结构。除非用户明确说“跳过调研”或任务完全基于用户提供的材料，否则执行本阶段。

## 流程

### 1. 生成多视角问题

围绕主题分别提出 2-3 个问题：

- **实践者**：如何落地、常见失败、成本与收益是什么？
- **架构师**：边界、依赖、权衡、适用与不适用场景是什么？
- **初学者**：最容易误解什么、需要哪些前置知识、最小示例是什么？

合并语义重复的问题，保留 5-8 个搜索问题。

### 2. 搜索与筛选

1. 使用 `WebSearch` 搜索每个核心问题。
2. 优先选择官方文档、标准组织、论文、原作者文章、知名工程团队复盘。
3. 对关键来源使用 `WebFetch` 阅读原文，不只依赖搜索摘要。
4. 交叉验证关键数字和强结论；无法交叉验证时降低可信度并避免写成确定事实。
5. 默认保留 3-5 个高价值来源，不为凑数量引入弱来源。

可信度分级：

- `high`：官方文档、标准、论文、原始数据或项目发布说明。
- `medium`：可信工程团队、专家实践文章，内容可被其他来源印证。
- `low`：聚合转载、无出处结论、营销内容；只能用于发现线索，不能支撑关键结论。

### 3. 生成素材卡

将结果保存为 JSON，建议路径为 `<article>.materials.json`：

```json
{
  "topic": "文章主题",
  "perspectives": ["practitioner", "architect", "beginner"],
  "cards": [
    {
      "id": 1,
      "source_name": "来源名称",
      "title": "原文标题",
      "source_url": "https://example.com/source",
      "published_at": "2026-07-01",
      "credibility": "high",
      "key_argument": "该来源支持的核心论点",
      "quotable_data": ["可核验的数据或原话"],
      "target_section": "计划使用的文章章节",
      "perspective": "architect"
    }
  ]
}
```

不要把推断写进 `quotable_data`。素材卡中的每条数据都必须能在来源中定位。

### 4. 调研增强大纲

先根据主题生成草案，再用素材卡补强：

- 为每个大纲节点绑定相关素材卡 ID。
- 如果某个核心章节没有可靠材料，继续搜索或明确该节属于作者分析。
- 如果调研推翻了原先假设，调整大纲，不要迁就初始结构。

### 5. 带引用写作

- 在可验证事实、统计数字、第三方结论后添加 `[n]`。
- 自己的分析、代码演示和常识性描述不强行引用。
- 编号按正文首次出现顺序连续排列。
- 文末生成 `## 参考引用`，每条包含来源、标题、日期（如有）和 URL。
- 完稿后运行：

```bash
python scripts/format_citations.py \
  --article-file article.md \
  --citations article.materials.json \
  --output article-cited.md
```

## 失败降级

- `WebSearch` 不可用：说明无法联网验证，请用户提供材料，或在其同意后基于现有知识写作。
- 来源打不开：不要引用搜索摘要中的具体数字；换用可访问的一手来源。
- 不同来源冲突：在正文呈现差异及统计口径，不擅自选取更吸引人的数字。
- 用户要求跳过：不伪造引用，文末不生成参考引用节。
