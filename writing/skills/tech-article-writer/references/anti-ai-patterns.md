# 中文 AI 写作模式审计

> 设计参考：`conorbronsdon/avoid-ai-writing` 的分层权重检测、结构与文体审计、两遍重写机制。

## 审计目标

去掉空泛、模板化和过度工整的表达，同时保留作者语气、技术准确性与必要术语。不要为了“像人”故意加入错别字、口语噪声或未经证实的个人经历。

## 三层词汇权重

脚本 `scripts/humanize_check.py` 使用以下权重：

- **高风险（5 分）**：值得注意的是、综上所述、不可或缺、至关重要、应运而生、方兴未艾、不言而喻、毋庸置疑、赋能、范式、生态闭环、降维打击、革命性、颠覆性、无缝衔接等。
- **中风险（3 分）**：本质上、从某种意义上说、进一步来说、与此同时、在此基础上、值得一提的是、不难发现、显而易见、由此可见、从而实现、有效地、旨在、助力等。
- **低风险（2 分）**：总的来说、换句话说、归根结底、一般而言、一方面/另一方面、首先/其次/最后等。

单个命中不是错误。结合出现频率、上下文和篇幅判断。技术术语、引用原文和必要总结可保留。

## 结构与文体检测

检查：

1. 连续三个以上段落长度过度接近，结构像模板填充。
2. 连续句子使用相同句首或相同排比骨架。
3. 过渡词密度高，逻辑主要靠“首先、其次、此外、因此”维持。
4. 每节都使用“定义→优势→挑战→未来”的对称结构。
5. 结论只重复标题，没有具体判断、边界或下一步。
6. 使用无法核验的“业内普遍认为”“大量实践证明”等权威暗示。

## 评分

```text
raw_score = Σ(命中次数 × 权重) + 结构模式分
score = min(100, round(raw_score / max(1, log2(中文字符数 / 100))))
```

- 0-20：优秀
- 21-40：良好，可发布
- 41-60：需要修改
- 61-100：模板化严重

运行：

```bash
python scripts/humanize_check.py --article-file article.md --verbose
```

## 两遍重写

### 第一遍：审计与改写

按命中分数从高到低处理：

- 空泛判断 → 换成事实、场景、数字、代码结果或明确立场。
- 套话过渡 → 删除，让上下文直接衔接；必要时补真实因果。
- 机械排比 → 改变句式和段落长度，只保留有信息增量的项。
- 过度确定 → 标注适用条件、限制和证据范围。
- 虚假权威 → 补引用，否则改成作者判断并说明依据。

### 第二遍：纠偏复读

从头阅读全文，检查：

1. 改写是否引入新套话或同义重复。
2. 技术含义、数字、引用是否被改坏。
3. 句子是否为了规避词表变得别扭。
4. 文章是否仍符合选定风格 profile。
5. 最终评分是否不高于 40。

评分只是报警器，不是优化目标。不要通过机械删词换取低分。

## 例外

- 代码、命令、引用块不参与检测。
- 技术领域中的“范式”等准确术语可保留，但应写清具体含义。
- 文末允许一次自然总结，不要求固定使用或禁用“综上”。
- 引用原文命中时不改写原文，只检查引用是否必要、准确。
